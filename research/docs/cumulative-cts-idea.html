Adaptive CTS Window 아이디어 정리

이 아이디어의 핵심은 단순한 cumulative CTS가 아니라, topology + collective + algorithm + protocol + receiver occupancy를 보고 receiver가 CTS window W를 동적으로 조절하는 것이다. 구현은 먼저 fake cumulative로 시작하고, 필요하면 이후 real cumulative로 확장한다.

Main idea: adaptive CTS window
First prototype: fake cumulative
Extension: real cumulative CTS

1. 문제의식

incast 위험은 모든 collective에서 같지 않다. 같은 receiver-driven admission이라도 어떤 workload는 큰 window가 pipeline 유지에 유리하고, 어떤 workload는 작은 window가 burst 억제에 필수적이다.

low-risk case intra-rack + AllReduce + Ring + LL/LL128 -> fan-in pressure relatively low -> pipeline occupancy is more important -> larger W is acceptable high-risk case cross-rack + AllToAll + Simple -> many-to-many + large step payload -> ingress burst and uplink pressure are high -> smaller W is safer
따라서 본체는 "CTS를 줄이자"가 아니라 "incast risk에 따라 서로 다른 CTS window를 주자"다.

2. 설계 원칙

Per-slot CTS

  • CTS 1개 = slot 1개 허가
  • 정밀도는 높음
  • reverse path jitter에 민감함

Fake Cumulative

  • 첫 구현 대상
  • per-slot CTS는 유지
  • receiver가 W개 slot을 미리 열어둠
  • CTS 패킷 수는 그대로지만 jitter 흡수 가능

Real Cumulative

  • 확장 구현 대상
  • CTS 1개 = 여러 future slot 허가
  • CTS packet/byte 감소 가능
  • IB control format 변경 필요

정책의 본체

  • receiver가 W를 결정
  • high-risk 조합에는 작은 W
  • low-risk 조합에는 큰 W
  • occupancy가 높으면 future grant shrink
즉 "cumulative"는 구현 형식이고, 실제 아이디어의 본체는 incast-risk-aware adaptive CTS window policy다.

3. 입력 파라미터

정적 한 변수만으로는 window를 정하기 어렵다. 첫 버전에서 최소한 아래 입력은 같이 봐야 한다.

파라미터 예시 값 의미 W에 주는 영향
topologyClass intra-rack, cross-rack Clos에서 uplink를 타는지 여부 cross-rack일수록 작게
collAPI AllReduce, AllToAll, AllGather, ReduceScatter fan-in / fan-out / many-to-many 구조 AllToAll일수록 작게
algorithm Ring, Tree collective 내부 traffic shape Tree fan-in 시 더 보수적으로
protocol Simple, LL, LL128 step payload와 burst granularity 차이 Simple일수록 작게
msgSizeClass small, medium, large latency-bound / throughput-bound 구분 large일수록 더 조심
activeSenders 1, 2, 4, 8 receiver에 동시에 몰리는 sender 수 많을수록 작게
freeSlots 0..N receiver가 실제로 열 수 있는 공간 최종 upper bound
occSlots 0..N current occupancy / backpressure 수준 높을수록 shrink

4. W 계산식

첫 버전은 학습 기반보다, 구현 가능한 위험 점수 기반 heuristic이 적절하다.

R = topoRisk + collRisk + algoRisk + protoRisk + sizeRisk + senderRisk + occRisk Wbase = lookup_window_from_risk(R) W = min(Wbase, freeSlots, perPeerCap, globalCap) if (occSlots >= HIGH_WATERMARK) W = 1 else if (occSlots <= LOW_WATERMARK) W = min(W + 1, Wmax) W = max(W, 1)
Risk score 추천 Wbase 의미
0-2 8 낮은 incast 위험, pipeline 우선
3-4 4 중간 위험, 균형
5-6 2 높은 위험, 보수적 admission
7 이상 1 매우 높은 위험, 사실상 per-slot 수준
freeSlots만 보고 window를 키우면 cross-rack AllToAll에서도 너무 공격적인 grant가 나올 수 있다. 반드시 workload semantics와 topology risk를 같이 봐야 한다.

6. 구현 경로

Phase A: Fake Cumulative

recvProxyProgress()에서 dynamic window로 irecv를 W개 미리 열어둔다. IB transport는 기존처럼 per-slot CTS를 계속 발급한다.

  • 장점: 구현이 쉽다
  • 장점: adaptive window 정책 자체를 검증할 수 있다
  • 한계: CTS 패킷 수는 줄지 않는다

Phase B: Real Cumulative

net_ib/common.h와 net_ib/p2p.cc를 바꿔, CTS 하나가 여러 future slot을 허가하게 만든다.

  • 장점: CTS packet/byte 감소 가능
  • 한계: wire/control format 수정 필요
  • 한계: direct/register path는 더 복잡하다
첫 논문/프로토타입의 중심 기여는 adaptive CTS window policy로 두고, real cumulative은 확장 설계로 두는 것이 안전하다.

7. 기대 효과

Traffic Shape Awareness
강화

topology와 protocol 차이를 window policy에 반영할 수 있다.

Sender Stall
완화

fake cumulative만으로도 reverse path jitter 민감도를 줄일 수 있다.

Pipeline Occupancy
향상

낮은 위험 workload에서는 큰 window로 pipeline을 더 잘 채운다.

Safety
유지

높은 위험 workload에서는 작은 window로 burst를 억제한다.

real cumulative까지 가면 여기에 CTS packet/byte 감소가 추가된다. 하지만 정책 아이디어 자체는 fake cumulative만으로도 충분히 검증 가능하다.

8. tradeoff

  • 장점: high-risk workload를 더 보수적으로 제어하고, low-risk workload에서는 pipeline을 더 공격적으로 유지할 수 있다.
  • 핵심 리스크: naive하게 큰 W를 주면 cross-rack AllToAll에서 burst를 키울 수 있다.
  • 필수 안전장치: freeSlots cap, perPeerCap, globalCap, high/low watermark hysteresis
  • 구현 난이도: fake cumulative은 비교적 쉽고, real cumulative은 IB control format 변경이 필요하다.
강한 claim은 "항상 throughput이 증가한다"가 아니라, "incast risk가 다른 workload에 서로 다른 CTS window를 주는 것이 더 좋은 tradeoff를 만든다"가 되어야 한다.

9. 한 문장 요약

이 아이디어의 본체는 cumulative CTS 자체가 아니라, topology / collective / algorithm / protocol / occupancy를 보고 receiver가 CTS window W를 동적으로 결정하는 adaptive admission policy다.
