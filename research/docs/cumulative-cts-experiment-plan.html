Experiment Plan

Adaptive CTS Window 실험 계획서

목표는 topology + collective + algorithm + protocol + occupancy에 따라 incast 위험이 실제로 다르다는 점을 보이고, 그 위험에 맞춰 receiver-side CTS window W를 동적으로 조절하는 정책이 stock NCCL의 fixed-depth admission보다 더 좋은 tradeoff를 내는지 입증하는 것이다.

Cluster: 8 nodes
Topology: 2 racks x 4 nodes, Clos
Network: RoCE v2 RDMA
Main implementation: fake cumulative

1. 목적과 핵심 가설

H1. Traffic shape 차이

topology, collective, algorithm, protocol에 따라 burst와 incast 위험이 실제로 다르다.

H2. 정책 효과

그 차이를 이용한 adaptive CTS window는 fixed window보다 더 좋은 throughput/latency tradeoff를 낸다.

H3. 구현 경로

첫 구현은 fake cumulative만으로도 정책 아이디어를 검증할 수 있고, real cumulative은 후속 최적화로 분리 가능하다.

이 연구의 1차 목표는 "CTS packet을 무조건 줄인다"가 아니라 "incast risk가 다른 workload에 서로 다른 window를 적용하는 것이 더 낫다"를 입증하는 것이다.

2. 제안 구조

Baseline receiver uses fixed-depth per-slot admission -> every recv post emits per-slot CTS -> same effective window across heterogeneous workloads Proposed estimate incast risk from: topology + collAPI + algorithm + protocol + occupancy + active senders -> choose W dynamically -> low-risk case: larger W -> high-risk case: smaller W -> if occupancy rises, shrink future window -> if occupancy drains, expand again
첫 구현은 fake cumulative다. 즉 per-slot CTS는 유지하되, receiver가 몇 step 앞까지 irecv를 미리 열어둘지 동적으로 조절한다. 이 단계에서는 CTS packet 수는 줄지 않는다.

3. 입력 파라미터와 W 계산식

3.1 입력 파라미터

파라미터 예시 값 역할
topologyClass intra-rack, cross-rack inter-rack uplink risk 반영
collAPI AllReduce, AllToAll, AllGather, ReduceScatter fan-in / many-to-many 정도 반영
algorithm Ring, Tree traffic shape 반영
protocol Simple, LL, LL128 burst granularity 반영
msgSizeClass small, medium, large large transfer 보수화
activeSenders 1, 2, 4, 8 receiver ingress fan-in 반영
freeSlots 0..N window의 물리적 upper bound
occSlots 0..N 현재 backpressure 수준 반영

3.2 계산식

R = topoRisk + collRisk + algoRisk + protoRisk + sizeRisk + senderRisk + occRisk Wbase = lookup_window_from_risk(R) W = min(Wbase, freeSlots, perPeerCap, globalCap) if (occSlots >= HIGH_WATERMARK) W = 1 else if (occSlots <= LOW_WATERMARK) W = min(W + 1, Wmax) W = max(W, 1)
Risk score 추천 Wbase 의미
0-2 8 낮은 위험, pipeline 유지 우선
3-4 4 중간 위험, 균형
5-6 2 높은 위험, 보수적 admission
7 이상 1 매우 높은 위험, per-slot 수준

  1. B2 적용

Phase 4. Topology-aware adaptive W

  1. B3 적용
  2. cross-rack에서 효과가 intra-rack보다 큰지 확인

Phase 5. Occupancy hysteresis

  1. B4 적용
  2. burst amplification, oscillation, tail latency를 줄이는지 확인

Phase 6. Optional real cumulative

  1. B5 구현 시 CTS packet/byte 감소를 추가로 측정

11. 가장 중요한 입증 메시지

  1. topology, collective, algorithm, protocol에 따라 incast risk가 실제로 다르다.
  2. 그 차이를 반영하지 않는 고정 admission window는 일부 workload에서 비효율적이다.
  3. adaptive CTS window는 high-risk 조합에서는 더 보수적으로, low-risk 조합에서는 더 공격적으로 동작한다.
  4. 그 결과 stock NCCL보다 더 좋은 throughput/latency tradeoff를 낸다.
  5. real cumulative은 가능하면 추가하되, 핵심 기여는 adaptive window policy 자체다.
